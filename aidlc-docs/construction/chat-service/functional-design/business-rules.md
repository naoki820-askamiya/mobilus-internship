# ビジネスルール

## BR-001: 担当割り当てルール（排他制御）

| 項目 | 内容 |
|------|------|
| ルール | 問い合わせの担当は「担当者未決定」状態のもののみ取得可能 |
| 条件 | `inquiry.status == WAITING (0) AND inquiry.assigned_operator_id IS NULL` |
| 違反時 | ConflictError（409）を返却 |
| 早い者勝ち | 同時に2人のオペレータが担当取得した場合、DBのトランザクションで先に更新したほうが取得成功 |

BOT対応中（`status=BOT`）の問い合わせは担当取得できない。オペレータ対応へ移行し `status=WAITING` になった時点で取得可能になる。稼働状態（離席/稼働）は担当取得の可否に使わない。

### 排他制御の実装方針
- SQLite のトランザクション＋ WHERE 条件による楽観的ロック
- `UPDATE inquiries SET assigned_operator_id = ?, status = 1 WHERE id = ? AND assigned_operator_id IS NULL AND status = 0`
- affected_rows == 0 の場合は ConflictError

## BR-002: チャット送信権限ルール

| 項目 | 内容 |
|------|------|
| エンドユーザ | 自分が開始した問い合わせにのみメッセージ送信可能 |
| オペレータ | 自分が担当する問い合わせにのみメッセージ送信可能 |
| BOT対応中 | `status == BOT` または `bot_state != NULL` のときは通常メッセージ送信不可 |
| 終了済み | `status == CLOSED` の問い合わせにはメッセージ送信不可 |

BOT質問と回答は REST API（`POST /api/chat/{inquiry_id}/bot/answer`）で処理する。WebSocketの通常メッセージは使わない。

### 権限マトリクス
| 送信者 | 問い合わせ状態 | 担当者 | 送信可否 |
|--------|-------------|--------|---------|
| エンドユーザ | bot (3) | - | ✗（通常メッセージ。BOT回答APIは可） |
| エンドユーザ | waiting (0) | - | ✓ |
| エンドユーザ | active (1) | 任意 | ✓ |
| エンドユーザ | closed (2) | - | ✗ |
| オペレータ | bot (3) | - | ✗ |
| オペレータ | waiting (0) | - | ✗（まだ担当していない） |
| オペレータ | active (1) | 自分 | ✓ |
| オペレータ | active (1) | 他人 | ✗ |
| オペレータ | closed (2) | - | ✗ |

## BR-003: セッション終了ルール

| 条件 | 動作 |
|------|------|
| エンドユーザが「終了」ボタンを押す | 即座にセッション終了 |
| ブラウザのタブを閉じる | WebSocket切断検知でセッション終了 |
| 30分間操作がない | タイムアウトでセッション終了 |
| BOTで「他に質問はない」を選択 | BOT完了として問い合わせ終了 |

### セッション終了時の共通処理
1. `inquiry.status` を `CLOSED (2)` に更新し、`bot_state` を `NULL` にする
2. `inquiry.closed_at` に現在時刻を設定
3. 既に終了済みの場合は何もしない（終了メッセージの重複保存を防ぐ）
4. システムメッセージ「ユーザーが退出しました」を Message テーブルに保存（BOT完了時は BOT メッセージ「解決してよかったです。お問い合わせありがとうございました。」を保存する）
5. 同じ問い合わせに接続中の相手へ終了を通知する
6. ConnectionManager から接続を削除する

### セッション終了後のオペレータ画面
- チャット画面にシステムメッセージが表示される
- メッセージ入力欄・送信ボタンが無効化（disabled）される
- 会話履歴（BOT質問・回答を含む）は引き続き閲覧可能

## BR-005: 問い合わせ一覧の取得ルール

問い合わせ一覧画面はページングせず、未完了と完了済みを分離して取得する。

| 項目 | 値 | 備考 |
|------|------|------|
| 未完了 | `GET /api/inquiries/open` | 全件。オペレータ視点の優先順 |
| 完了済み | `GET /api/inquiries/closed` | 最新 `CLOSED_INQUIRY_DISPLAY_LIMIT`（50）件 |
| レガシー | `GET /api/inquiries` | ページング付き全件。移行期間中は残置 |

未完了の優先順（`DISPLAY_STATUS_PRIORITY`）:

1. 自分の担当
2. 担当者未決定
3. BOT対応中
4. 担当外
5. （完了済みは別API）

同じ優先度では作成日時の古い順、IDの昇順。完了済みは完了日時の新しい順、IDの降順。

## BR-006: WebSocket接続ルール

### エンドユーザ接続
| 項目 | 内容 |
|------|------|
| 認証 | 不要 |
| 接続条件 | 作成済みの `inquiry_id` が存在し、終了していないこと。問い合わせは BOT開始API で先に作成する |
| BOT中の用途 | 切断検知と、オペレータ対応へ切り替わったあとの通常チャット待ち |
| BOT質問の配信 | HTTPレスポンスで返す。WebSocketでは重複配信しない |
| 切断条件 | タブ閉じ / タイムアウト / 明示終了 / BOT完了 |

### オペレータ接続
| 項目 | 内容 |
|------|------|
| 認証 | 必要（セッションCookieで検証） |
| 接続条件 | 対象問い合わせの担当者であること |
| 切断条件 | ログアウト / ブラウザ閉じ |
| 担当外の閲覧 | REST API経由で履歴閲覧は可（WebSocket接続は不可） |
| BOT対応中 | 担当者ではないため WebSocket 接続不可。履歴閲覧は可 |

## BR-011: オペレータ稼働状態ルール

| 項目 | 内容 |
|------|------|
| 状態 | `AWAY = 0`（離席）、`AVAILABLE = 1`（稼働） |
| 初期状態 | `AWAY`。本人が明示的に切り替えた場合のみ `AVAILABLE` とする |
| 状態の保持 | オペレータ単位で保存し、ログイン・ログアウト・セッション期限切れでは変更しない |
| 実効稼働 | `AVAILABLE` かつ基準時刻に有効なセッションを1件以上持つこと |
| 待ち時間 | 実効稼働のオペレータだけを稼働人数へ含める |
| 複数セッション | 同一オペレータは重複して数えない |
| 担当取得・チャット | 稼働状態を可否判定へ使用せず、離席中も従来どおり利用可能とする |
| 状態履歴 | 保存しない。現在状態のみを保持する |
| 更新API | `PATCH /api/auth/me/availability`。遷移先を明示し、同一状態の再送も成功とする |

## BR-012: BOT事前質問ルール

| 項目 | 内容 |
|------|------|
| 開始 | エンドユーザがチャット画面を開くと `POST /api/chat/start` で問い合わせを作成する |
| 質問の正 | 質問文・選択肢・遷移はバックエンドの `app/bot/questions.py` を唯一の定義元とする |
| 状態遷移 | フロントは分岐せず、APIが返す `QUESTION` / `OPERATOR` / `COMPLETED` に従う |
| 二重回答 | 回答中はUIを無効化する。DBの `bot_state` とリクエストの `state` が不一致なら 409 |
| オペレータ移行 | `status` を WAITING、`bot_state` を NULL にし、「オペレーターにおつなぎします。少々お待ちください。」を保存する |
| 完了 | `status` を CLOSED、`bot_state` を NULL にし、完了メッセージを保存して WebSocket へ `closed` を通知する |

### 状態遷移

```text
INQUIRY_CATEGORY
├─ 料金 → SIZE_QUESTION
└─ その他 → オペレーター対応

SIZE_QUESTION
├─ サイズ入力 → 料金計算 → PRICE_RESOLUTION
├─ サイズの測り方がわからない → オペレーター対応
└─ サイズに関係ない質問です → オペレーター対応

PRICE_RESOLUTION
├─ はい（解決した） → ADDITIONAL_QUESTION
└─ いいえ（解決していない） → オペレーター対応

ADDITIONAL_QUESTION
├─ はい（他に質問がある） → INQUIRY_CATEGORY
└─ いいえ（他に質問はない） → 問い合わせ終了
```

### 料金計算

三辺合計 = 縦 + 横 + 高さ（cm）。境界値と料金は `PRICE_TIERS` で管理する。

| 三辺合計 | 料金 |
|---------|------|
| 150cm 以下 | 250円 |
| 150cm 超、200cm 以下 | 500円 |
| 200cm 超、250cm 以下 | 1,000円 |
| 250cm 超 | 1,500円 |

## BR-013: 推定待ち時間ルール

現在の待ち時間（`GET /api/wait-time`、認証不要）:

| 記号 | 意味 | 取得方法 |
|------|------|----------|
| \(A\) | 対応中件数 | `status = ACTIVE` |
| \(W\) | 待機件数 | `status = WAITING` かつ未割り当て |
| \(L\) | 負荷 | \(L = A + W\)（BOT対応中は含めない） |
| \(N\) | 稼働オペレータ数 | `availability_status = AVAILABLE` かつ有効セッションを持つ operator_id の重複なし件数 |
| \(P\) | 同時対応数 | `CONCURRENT_INQUIRIES_PER_OPERATOR`（2） |
| \(T\) | 1件あたり想定時間（分） | `ESTIMATED_MINUTES_PER_INQUIRY`（5） |
| \(C\) | 総キャパシティ | \(C = N \times P\) |

\[
\text{estimated\_wait\_minutes} =
\begin{cases}
\texttt{null} & (N = 0) \\
0 & (N > 0 \land C > L) \\
\left\lceil \dfrac{(L - C) \times T}{C} \right\rceil & (N > 0 \land C \le L)
\end{cases}
\]

時系列待ち時間（`GET /api/wait-time/hourly`）は、取得日前日 8:00〜18:00 のモック値を1時間刻みで11件返す。実データ集計ではない。

## BR-014: サマリーボード集計ルール

| 項目 | 内容 |
|------|------|
| 対象 | 認証済みオペレータ。選択日の `inquiries.created_at` が当日 00:00:00 以上、翌日 00:00:00 未満 |
| セッション | 問い合わせ1件を1セッションとする（ログイン用 `sessions` ではない） |
| 初回応答 | 最初のオペレータメッセージ時刻 − 問い合わせ作成時刻。未応答は平均から除外 |
| 時間帯 | 0時〜23時の24件を必ず返す。件数0の時間帯は `session_count=0`、平均は `null` |
| 単位 | APIは秒の整数。画面は「1分30秒」のように整形する |
