# BOT事前質問機能 ビジネスロジックモデル（差分）

本書には、既存の`aidlc-docs/construction/chat-service/functional-design/business-logic-model.md`から変更・追加するビジネスロジックのみを記載する。

## 1. 問い合わせステータスの追加

既存の問い合わせステータスに、以下を追加する。

```text
3: BOT（BOT対応中）
```

`status=BOT`の場合、オペレーターによる担当取得および通常チャットへの参加を許可しない。

---

## 2. BOT質問状態の追加

`Inquiry`に、現在のBOT質問を表す`bot_state`を追加する。

```text
INQUIRY_CATEGORY
    問い合わせ内容質問

SIZE_QUESTION
    サイズについての質問

PRICE_RESOLUTION
    料金計算結果の表示および解決確認

ADDITIONAL_QUESTION
    他の質問有無の確認
```

`bot_state`は`status=BOT`の場合のみ値を持つ。

オペレーター対応へ移行する場合、または問い合わせを終了する場合は`NULL`へ更新する。

---

## 3. 問い合わせ作成タイミングの変更

既存の「初回メッセージ送信時にInquiryを作成する」処理を、以下へ変更する。

### 問い合わせ作成（BOT質問開始時）

```text
1. エンドユーザがBOT質問を開始する
2. Inquiryを以下の状態で作成する
   - status = BOT
   - bot_state = INQUIRY_CATEGORY
3. 最初のBOT質問「問い合わせ内容を選択してください」を作成する
4. BOT質問をMessageとしてDBへ保存する
5. 保存したBOT質問をエンドユーザへ返す
6. エンドユーザの接続を作成したInquiryへ紐づける
```

以降のBOT質問、ユーザ回答、オペレーターとのチャットは、同じInquiryへ紐づける。

---

## 4. BOT質問・回答処理の追加

### BOT質問の保存

BOT質問と料金計算結果は、既存の`Message`として保存する。

```text
sender_type = BOT
content = 質問文または料金計算結果
```

このため、既存の送信者タイプに`BOT`を追加する。

### BOT質問定義・選択肢の管理

BOTの質問文、質問形式および提示する選択肢はDBへ保存せず、バックエンドのコードで質問状態ごとに管理する。

```text
INQUIRY_CATEGORY
    質問文: 問い合わせ内容を選択してください
    質問形式: 選択式
    選択肢:
        - 料金
        - その他

SIZE_QUESTION
    質問文: サイズについて教えてください
    質問形式: サイズ入力・選択式
    選択肢:
        - サイズの測り方がわからない
        - サイズに関係ない
```

質問ごとに選択肢の個数が異なるため、選択肢は固定カラムではなく、質問定義内のリストとして保持する。

DBへ保存するのは、実際にエンドユーザへ表示したBOT質問文と、エンドユーザが実際に回答した内容のみとする。

```text
保存する:
    - 実際に表示したBOT質問文
    - 料金計算結果
    - ユーザが選択または入力した回答

保存しない:
    - BOTが提示した選択肢の一覧
    - 質問形式
    - 質問間の遷移条件
```

選択肢や遷移条件を管理画面から変更する要件が追加された場合に、質問定義をDBで管理する方式を再検討する。

### 選択肢の表示と回答後の扱い

BOT質問の選択肢は、現在回答可能な最新の質問に対してのみ表示する。

```text
回答前:
    BOT「問い合わせ内容を選択してください」
    [料金] [その他]

回答後:
    BOT「問い合わせ内容を選択してください」
    USER「料金」
```

ユーザが選択肢を押した後は、以下のように処理する。

```text
1. 回答処理中は選択肢ボタンを無効化し、二重回答を防止する
2. 回答の保存に成功したら、回答済みBOT質問から選択肢ボタンを削除する
3. 選択した内容を通常のユーザメッセージと同じ形式で表示する
4. 次のBOT質問がある場合は、その質問にだけ新しい回答UIを表示する
5. 回答の保存に失敗した場合は、選択肢ボタンを再度有効化する
```

過去のBOT質問は通常のチャット履歴として表示し、選択肢を再表示しない。

現在回答可能な質問は`bot_state`およびBOT質問の`message_id`で特定する。`sender_type=BOT`であることだけを条件に選択肢を表示しない。

### ユーザ回答の保存

BOT質問に対するユーザ回答は、既存の`Message`として保存する。

```text
sender_type = ENDUSER
content = 選択内容または入力内容
```

### 次質問の決定

```text
1. 対象Inquiryのstatusとbot_stateを取得する
2. statusがBOTであることを確認する
3. 現在のbot_stateに対して回答内容が正しいことを確認する
4. ユーザ回答をMessageとして保存する
5. 現在状態と回答内容から次の状態を決定する
6. 次の質問がある場合はBOTメッセージとして保存する
7. bot_stateを次の状態へ更新する
8. 次の質問、オペレーター対応、終了のいずれかへ遷移する
```

ユーザ回答の保存、次のBOT質問の保存、`bot_state`の更新は一連の処理として行う。

## 5. BOT状態遷移の追加

```text
INQUIRY_CATEGORY
├─ 「料金」
│   → SIZE_QUESTION
└─ 「その他」
    → オペレーター対応

SIZE_QUESTION
├─ 「サイズを入力」
│   → 料金を計算
│   → PRICE_RESOLUTION
├─ 「サイズの測り方がわからない」
│   → オペレーター対応
└─ 「サイズに関係ない」
    → オペレーター対応

PRICE_RESOLUTION
├─ 「解決した」
│   → ADDITIONAL_QUESTION
└─ 「解決していない」
    → オペレーター対応

ADDITIONAL_QUESTION
├─ 「他に質問がある」
│   → INQUIRY_CATEGORY
└─ 「他に質問はない」
    → 問い合わせ終了
```

料金計算結果と「解決しましたか？」は、1つのBOT質問として同時に表示する。

「他に質問がある」が選択された場合は、同じInquiryを利用して`INQUIRY_CATEGORY`へ戻る。

## 6. 料金計算処理の追加

### サイズ入力

エンドユーザへ、対象物の以下の3辺をセンチメートル単位で入力させる。

```text
- 縦（cm）
- 横（cm）
- 高さ（cm）
```

各入力値は0より大きい数値を必須とする。

入力値が未入力、数値以外、または0以下の場合は料金を計算せず、`SIZE_QUESTION`のまま再入力を求める。

ユーザ回答として、3辺の入力値を以下のようにMessageへ保存する。

```text
縦100cm、横30cm、高さ20cm
```

### 料金計算ルール

料金は体積ではなく、入力された3辺の長さの合計で算出する。

```text
三辺合計 = 縦 + 横 + 高さ
```

判定に利用する境界値と料金は定数として管理する。

```text
三辺合計が150cm以下
    → 250円

三辺合計が150cmより大きく200cm以下
    → 500円

三辺合計が200cmより大きく250cm以下
    → 1,000円

三辺合計が250cmより大きい
    → 1,500円
```

### 料金計算フロー

```text
1. SIZE_QUESTIONで入力された縦・横・高さを取得する
2. 3辺がすべて有効な値であることを検証する
3. 3辺の長さを合計する
4. 三辺合計に対応する料金を決定する
5. 料金計算結果と解決確認をBOTメッセージとして保存する
6. bot_stateをPRICE_RESOLUTIONへ更新する
7. 料金計算結果と「解決しましたか？」を同時に表示する
```

料金計算結果のBOTメッセージには、三辺合計と算出した料金を含める。

```text
三辺の合計は150cmです。
料金は250円です。解決しましたか？
```

---

## 7. オペレーター対応への移行処理の追加

BOTの回答結果がオペレーター対応となった場合、以下を行う。

```text
1. inquiry.statusをBOTからWAITINGへ更新する
2. inquiry.bot_stateをNULLへ更新する
3. 通常チャットのメッセージ送信を許可する
4. オペレーターによる担当取得を許可する
```

BOT対応中に保存した質問と回答は、オペレーターが既存のメッセージ履歴から確認できるようにする。

---

## 8. 通常メッセージ送信条件の変更

既存のメッセージ送信時のステータス確認に、以下を追加する。

```text
inquiry.status == BOT
または inquiry.bot_state != NULL
    → 通常メッセージ送信を拒否
```

オペレーター対応へ移行して`status=WAITING`かつ`bot_state=NULL`になった後、通常メッセージ送信を許可する。

---

## 9. 問い合わせ終了条件の追加

既存の問い合わせ終了イベントに、以下を追加する。

```text
「他に質問はありますか？」で「いいえ」を選択した
```

BOT質問から終了する場合も既存の問い合わせ終了処理を実行し、追加で`inquiry.bot_state`を`NULL`へ更新する。

---

## 10. 問い合わせ一覧の表示ステータス追加

既存の表示ステータス算出に、以下を追加する。

```text
status == BOT
    → 「BOT対応中」
```

`status=BOT`の問い合わせは一覧へ表示するが、担当取得およびチャット参加を許可しない。

`status=WAITING`へ移行した時点で担当取得を許可する。
