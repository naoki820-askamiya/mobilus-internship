# サンプルデータベースの要件定義

作成範囲

20260801 ~ 20260807までの１週間のデータを作成する

## データ定義

- 1週間における1日の平均利用者数は225人
- 日ごとに平均から±50人程度のばらつきを持たせる
- 営業時間 9:00 ~ 17:00
- ピーク時間　9:00~12:00, 16:00~17:00
- ピーク時間に全体の７割がくる
- オペレーター1名につき、同時に2人まで対応できる
- オペレーターは12:00~13:00は1名のみ
- チャットの内容は適当でいい
- セッションは3分から10分程度・平均が5ふんくらいになる
- 過去のログとして用意するのですべて問い合わせが完了していることにする

## データ生成上の前提

このサンプルでは以下のように解釈する。

- 9:00〜17:00は問い合わせの受付時間とする。
- 通常は2名が各2セッション、12:00〜13:00は1名が2セッションまで同時対応する。
- 1日の利用者数は175〜275人とし、7日間の平均を225人にする。
- 曜日傾向として金曜を最も多く、土日を少なくする。
- 10時と16時を利用者数の頂点とし、9時は11時より少し多くする。
- 11時以降は昼へ向かって減少し、15時は16時のピークへ向かって増加させる。
- 時間帯別の基本比率に±3%の揺らぎを加え、山型を崩さない範囲で日ごとの差を作る。
- 同じ時間帯の中では問い合わせ時刻を適度に分散し、非現実的な秒単位の集中を避ける。
- 対応開始から完了までをセッションの対応時間とし、3〜10分、平均約5分にする。
- 17時直前に受け付けた問い合わせは、17時以降に完了する場合がある。
- 初回応答までの待ち時間は対応時間に含めない。
- 乱数seedを固定し、誰が実行しても同じ集計データを再現できるようにする。

## 作成方法

バックエンドディレクトリで以下を実行する。

```bash
cd backend
source venv/bin/activate
python -m scripts.create_sample_db
```

デフォルトでは `backend/sample_chat_service.db` を作成する。既に存在するDBを再作成する場合は `--force` を指定する。

```bash
python -m scripts.create_sample_db --force
```

開始日、出力先、乱数seedは引数で変更できる。

```bash
python -m scripts.create_sample_db \
  --database sample_chat_service.db \
  --start-date 2026-08-01 \
  --seed 20260801 \
  --force
```

## サンプルDBを使用した起動方法

ターミナルを2つ開き、バックエンドとフロントエンドをそれぞれ起動する。

### バックエンド

```bash
cd backend
source venv/bin/activate
DB_PATH="$(pwd)/sample_chat_service.db" python -m app.main
```

### フロントエンド

```bash
cd frontend
nvm use 24
npm run dev
```

環境変数を指定しない通常起動では、従来どおり `chat_service.db` を使用する。

```bash
python -m app.main
```

## 再現されるデータ

- 2026-08-01から2026-08-07までの7日分
- 1日175〜275件、7日間の平均225件
- 各日の問い合わせの70%がピーク時間帯に発生
- 各オペレーターは最大2セッションを同時対応
- 2名のうち1名は12:00〜13:00に対応しない
- 全問い合わせが担当者割り当て済み・完了済み
- 問い合わせ、最初のオペレーター返信、ユーザー返信、退出メッセージを保存

生成された `.db` ファイルは `.gitignore` の対象であり、Gitにはスクリプトだけを保存する。
